# Масштабирование HH AI Agent

## Узкое место сейчас

Поиск вакансий — **тяжёлый**: hh.ru + AI (1–3 мин на запрос). На одном VPS (2 vCPU / 4 GB) комфортно **~20–50 активных пользователей в день**, не тысячи одновременно.

## Уже в проекте (после обновления)

| Что | Зачем |
|-----|--------|
| `UVICORN_WORKERS=2` | API обрабатывает несколько запросов параллельно |
| Пул PostgreSQL | Больше одновременных подключений к БД |
| Общий httpx в боте | Меньше накладных расходов на HTTP |
| Дайджест с `DIGEST_CONCURRENCY=3` | Не один пользователь за другим |
| `last_digest_at` | Нет повторных дайджестов за день |
| Кэш AI-анализов в поиске | Меньше вызовов OpenRouter |
| Лимит списывается после успешного поиска | Справедливее при ошибках |

## Настройки в `.env` на сервере

```env
UVICORN_WORKERS=2
DB_POOL_SIZE=10
DB_MAX_OVERFLOW=20
DIGEST_CONCURRENCY=3
AI_REQUEST_DELAY_SEC=0.5
```

На VPS 4+ GB RAM можно `UVICORN_WORKERS=3`. Больше 4 воркеров на 2 vCPU обычно не даёт выигрыша.

Деплой:

```bash
cd /opt/hh-ai && git pull && docker compose up -d --build
```

## Когда пользователей станет много (100+ в день)

1. **Очередь задач** (Redis + Celery/RQ): поиск в фоне, бот отвечает «ищу…» и шлёт результат когда готово.
2. **Webhook вместо polling** для Telegram — стабильнее при нагрузке.
3. **Redis для FSM** — если запустите 2+ реплики бота.
4. **Отдельный сервер/воркер** только для AI-поиска.
5. **Увеличить VPS** (4 vCPU, 8 GB) или managed Postgres.

## Мониторинг

```bash
docker stats
docker compose logs api --tail 50
docker compose logs bot --tail 50
```

Смотрите: RAM > 90%, постоянные рестарты, 502 от API.

## Один бот = один процесс

Не запускайте два контейнера `bot` с одним `BOT_TOKEN` — Telegram отдаст обновления только одному.
